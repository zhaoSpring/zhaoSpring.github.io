MCP介绍

MCP是什么？

MCP 全称 模型上下文协议（Model Context Protocol），由 Anthropic 在 2024 年 11 月推出，是一个开源通信标准。简单说，它给 AI 装了个“万能转接头”，让 AI 能跟外部工具、数据、系统无缝对接。可以将 MCP 视为 AI 应用的 USB-C 端口。正如 USB-C 提供了一种将设备连接到各种外围设备和配件的标准化方式一样，MCP 提供了一种将 AI 模型连接到不同数据源和工具的标准化方式。

like：

  • AI应用 ==> 电脑主机
  • MCP ==> USB 协议
  • MCP Server ==> 各种 USB 设备（U盘、摄像头、麦克风等）

核心组件：
MCP 通过以下核心组件实现功能：

  1. 资源（Resources）： 公开数据（如文件、数据库记录），支持文本和二进制格式。
  2. 提示（Prompts）： 定义可复用的交互模板，驱动工作流。
  3. 工具（Tools）： 提供可执行功能（如 API 调用、计算），由模型控制。
  4. 采样（Sampling）： 服务器通过客户端请求 LLM 推理，保持安全隔离。
  5. 根（Roots）： 定义服务器操作范围（如文件路径、API 端点）。

传输机制：
MCP 为客户端-服务端通信定义了两种标准传输机制：

  1. 标准输入输出 (stdio)： 使用标准输入/输出进行通信，适用于本地进程
  2. 服务器发送事件 (SSE)： 使用 Server-Sent Events（服务器推送事件）进行服务器到客户端的消息传递，使用 HTTP POST 进行客户端到服务器的消息传递

想深入了解？看 官方介绍。

MCP能干什么？

MCP 能让 AI 从“嘴炮王”变成“实干家”，以下是几个例子：

  1. 连工具：用 GitHub 管理代码、用 12306 订票查票、用 高德地图 导航、用 快应用编程助手 创建快应用。
  2. 查数据：直接看你电脑文件、数据库记录，甚至网上实时信息。
  3. 干复杂活儿：写网页时，AI 能查代码、生成图片、调试页面，一条龙搞定。
  4. 人机协作：AI 干一半问你意见，你点头它再继续。

如何使用MCP？

  1. 选择 / 构建 支持 MCP 的客户端

MCP 客户端是 AI 的“操作台”：

  • 现有客户端： 例如，Claude 客户端、支持 MCP 的 IDE（如 Cursor、Windsurf）、VS Code 插件（如 Cline、Continue）等。
  • 自定义客户端： 如果您希望根据特定需求构建自己的客户端，可以使用 MCP 提供的 SDK（如 Python、Node.js、Java 等）进行开发。
  1. 获取MCP Server

MCP 在需要与多种外部资源和工具交互的应用场景中具有显著优势。具体体现在：

  • 生态： MCP 提供很多现成的插件，你的 AI 可以直接使用。

从0开始实现MCP Server

MCP生态正在快速发展，越来越多企业和开发者加入MCP标准，使AI能力边界不断扩展。MCP Server 是你构建智能体最重要的“外挂工具”集合，让大模型也能拥有连工具、查数据、干复杂活儿的能力，比如：生成快应用代码、地图导航等等。
在特定业务场景中，我们也能自己实现MCP Server，接入AI应用帮我们解决问题。

什么是MCP Server？

MCP Server 是一个中间层服务器，它主要负责处理和管理 AI 模型的上下文信息，确保模型能够高效且准确地理解和响应用户请求。MCP Server可以提供三种主要类型的功能：

  1. 资源： 客户端可以读取的类似文件的数据（如 API 响应或文件内容）
  1. 工具： LLM 可调用的函数（一般需用户批准）
  1. 提示： 帮助用户完成特定任务的预写模板

MCP Server与Client如何通信？

MCP Server需要连接到传输协议才能与MCP Client通信。服务器的启动方式取决于所选择的传输协议。

  • 消息格式
    MCP 使用 JSON-RPC 2.0 作为其传输格式。传输层负责将 MCP 协议消息转换为 JSON-RPC 格式进行传输，并将接收到的 JSON-RPC 消息转换回MCP 协议消息。
    使用的 JSON-RPC 消息主要有三种类型：
  1. 请求（Requests）
  1. 响应（Results）
  1. 通知（Notifications）

示例： 客户端通过resources/list端口请求资源列表，服务器返回可用资源：

  • 实现传输层
    MCP 协议支持多种传输机制，包括 stdio、Server-Sent Events（SSE） 。传输均采用JSON-RPC 2.0格式，确保消息一致性。







传输方式 标准输入输出 (stdio) 服务器发送事件 (SSE)
工作方式
  • 客户端和服务器通过标准输入输出流（stdin/stdout）通信
  • 客户端发送命令和数据，服务器执行后通过标准输出返回结果
  • 客户端通过 HTTP GET 请求与服务器建立连接
  • 服务端通过 HTTP POST 请求与客户端实现流式通信
应用场景
  • 构建命令行工具
  • 实现本地集成
  • 需要简单的进程通信
  • 使用 shell 脚本
  • 服务器主动推送数据
  • 实时聊天
  • 天气预报
  • 新闻更新等实时数据场景
TypeScript (Server) 实现 
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

const server = new McpServer({

name: “example-server”,

version: “1.0.0”

});

// … set up server resources, tools, and prompts …

const transport = new StdioServerTransport();

await server.connect(transport);

 
import express from “express”;

import { McpServer } from “@modelcontextprotocol/sdk/server/mcp.js”;

import { SSEServerTransport } from “@modelcontextprotocol/sdk/server/sse.js”;


const server = new McpServer({

name: “example-server”,

version: “1.0.0”

});

// … set up server resources, tools, and prompts …

const app = express();

let transport: SSEServerTransport | undefined = undefined;


app.get(“/sse”, async (req, res) => {

transport ??= new SSEServerTransport(“/messages”, res);

await server.connect(transport);

});


app.post(“/messages”, async (req, res) => {

await transport?.handlePostMessage(req, res);

});


app.listen(3001);

从0开始搭建MCP Client

什么是MCP Client？

MCP-Client作为 AI 的“操作台”，是连接AI模型（如Claude、GPT等大型语言模型）与外部数据源、工具和Server的桥梁。
MCP Client与MCP Server调用流程如下：

为什么要自己写MCP Client？

目前，流行的MCP Client包括Claude 客户端、支持 MCP 的 IDE（如 Cursor、Windsurf）、VS Code 插件（如 Cline、Continue）等。
虽然官方或第三方 MCP Client 已经提供了基础能力，但在以下场景中，建议考虑自行实现 MCP Client 以满足业务的差异化需求：

  1. 需要整合本地系统或私有服务
    典型场景：存在内网服务、私有 API、本地脚本或数据库，官方 Client 无法直接访问。需将已有系统能力封装成 MCP 工具供智能体调用。

示例：公司内部有一个内网报表系统，无法对外开放API。通过自建 MCP Client，可将报表生成功能注册成 tool，支持在智能体中用自然语言直接调用。

  1. 对权限控制与安全性有更高要求
    典型场景：业务涉及敏感数据、合规审计、权限隔离等场景。需自定义认证、鉴权、访问控制、数据加密、调用频控等安全策略。

示例：处理金融、医疗、政务等敏感数据，需对每次 tool 调用进行身份校验与操作审计。

  1. 业务逻辑复杂，需要定制化控制
    典型场景：需要工具链组合、跨工具调用、多步工作流等复杂流程控制。需实现任务编排、状态管理、异常处理与重试机制等。

示例：客服机器人需完成“工单创建 → 审核 → 分派 → 通知”多步骤流程，需在 MCP Client 中实现状态流转逻辑。

  1. 需支持私有部署或离线运行
    典型场景：部署环境不允许访问公网（如内网部署、边缘计算、国产化环境）。需在本地完整运行 MCP 协议栈，无需依赖外部托管服务。

示例：部署在政府机关内网，无法访问外网，必须完全本地化运行智能体与工具。

  1. 需要增强调试、监控与可观测性
    典型场景：需要更细粒度的日志、性能指标、调用链路追踪等。便于开发调试、问题定位和日常运维。

示例：在工具异常频繁时，通过自定义日志与监控快速定位是哪一步出现异常参数或超时。

  1. 协议扩展与兼容性适配需求
    典型场景：需支持 MCP 标准协议暂未覆盖的新字段、新指令或特殊输入输出格式。与遗留系统或特殊通信协议对接时需自定义协议适配层。

示例：某工业控制系统只支持特定二进制协议，通过 MCP Client 适配器将自然语言请求转换成底层控制指令。

总结： 当你的场景需要整合内外系统、强化安全控制、承载复杂流程、支持私有化部署或扩展协议能力时，自建 MCP Client 是更具性价比的选择！

如何实现一个A2UI 智能体

发表于2026-01-22|更新于2026-01-23|ai
|浏览量:

上一篇文章了解了A2UI协议，这篇文章我们来了解一下如何实现一个A2UI Agent。

要实现一个支持 A2UI 的智能体，本质上是让 Agent 具备“理解场景并生成结构化交互界面”的能力。

A2UI智能体需要的能力

三个维度拆分：协议表达能力、逻辑编排能力、以及前端感知能力。

协议表达能力

  • 身份声明 (Self-Description)： Agent 必须能通过 AgentCard 声明自己的 capabilities。
  • 格式规范 (Schema Adherence)： Agent 必须能严格输出符合 A2UI 标准的 JSON 格式。
  • 流式包装 (Streaming Support)： 由于 A2UI 界面往往很大，Agent 需要支持流式输出，让 UI 组件能“渐进式”地在前端生长出来。

逻辑编排能力

  • 场景判断 (Context Awareness)： Agent 需要判断当前对话是否需要 UI。
  • 模板填充 (Template Mapping)： Agent 通常不需要从零生成 UI 代码，而是将业务数据（如餐厅名、价格）填充进预设的 A2UI 模板中。
  • 任务状态维护 (Task Management)： Agent 需要管理任务的生命周期（Submitted -> Working -> Input-Required）。

前端感知与反馈能力 (Interaction Loop)

  • 动作响应 (Action Handling)： Agent 必须能理解来自 UI 组件的 action_id。
  • 静态资源管理： 如你之前在 main.py 中看到的，Agent 必须具备提供静态资源（图片、图标）URL 的能力，确保渲染器能拉取到素材。

案例分析

参考 A2UI/samples/agent/adk/restaurant_finder 案例：

为了实现支持A2UI的智能体，新建python项目环境，引入 google-adk 、 a2a-sdk 、 a2ui 等依赖。

定义 A2UI Schema 和 UI 模板

  1. A2UI Schema：约束 LLM 输出结构
    A2UI_SCHEMA 是一个 JSON Schema 字符串 ，描述了 一条 A2UI 消息 该长什么样（包含 beginRendering / surfaceUpdate / dataModelUpdate / deleteSurface 等字段）。
    文件 ：prompt_builder.py：

在 agent.py 里，初始化时把它加载成 Python 对象，并包装成“数组 Schema”，因为最终 LLM 输出的是一个 消息列表 ：

  1. UI 模板：告诉 LLM UI 组件树长什么样
    文件 ： a2ui_examples.py

里面定义了 RESTAURANT_UI_EXAMPLES ，包含 4 段模板：

  • SINGLE_COLUMN_LIST_EXAMPLE ：少量餐厅，单列列表
  • TWO_COLUMN_LIST_EXAMPLE ：餐厅很多，两列卡片排布
  • BOOKING_FORM_EXAMPLE ：预订表单界面
  • CONFIRMATION_EXAMPLE ：预订成功确认界面

这些模板本质上是 A2UI 消息列表的示例 JSON ，用 {{ ... }}作为占位符，方便用 str.format 注入 base_url 等。

  1. 拼装成最终 Prompt：get_ui_prompt / get_text_prompt
    文件 ： prompt_builder.py
  • get_ui_prompt(base_url, examples) 会返回一整段系统 Prompt：
    • 说明响应格式：
      • 上半部分 是自然语言回复
      • 用分隔符 ---a2ui_JSON---
      • 下半部分 是一段 raw JSON，且是“ A2UI 消息列表 ”
    • 给出“什么时候用哪段模板”的规则：
      • 查餐厅：根据数量选择单列 / 双列模板
      • 预订：用 BOOKING_FORM_EXAMPLE
      • 确认：用 CONFIRMATION_EXAMPLE
    • 把 A2UI_SCHEMA 嵌到 Prompt 里，强化 LLM 遵守 Schema
  • get_text_prompt() 则是纯文本模式下的版本，没有 UI JSON，只要求调用 get_restaurants 工具，并返回可读文本。

实现业务工具（Tools）

按业务实现一个或多个工具函数（查数据库、调用第三方 API 等），在 Agent 中把这些工具注册给 LlmAgent(tools=[...])。这里，先用 ADK 的工具规范实现函数： get_restaurants
Google ADK是一个用于开发和部署AI Agents 的灵活、模组化的工具，文档：https://google.github.io/adk-docs/
文件 ： tools.py

  • 工具函数签名符合 ADK 的要求，接收 ToolContext ，可以从中读到 state （这里用来替换图片 URL 的 base_url）
  • 从 restaurant_data.json 里读出预置列表，裁剪前 count 个，并根据 base_url 修正图片地址
  • 返回值是 字符串形式的 JSON 数组 ，后面 LLM 会直接用这个数据去填充 UI 的 dataModelUpdate.contents

实现 LLM Agent 类

文件：agent.py

  1. Agent的系统指令
    首先定义 AGENT_INSTRUCTION ，描述agent逻辑：
  • 查餐厅时：必须调用 get_restaurants ，根据 count 决定用哪个 UI 模板
  • 收到 “USER_WANTS_TO_BOOK…” 这类文本时：生成预订表单 UI
  • 收到 “User submitted a booking…” 时：生成确认 UI
  1. 构建 LlmAgent
    在 RestaurantAgent.init 中调用 _build_agent，构造 LlmAgent ，根据是否使用 UI 选择不同 Prompt
  • use_ui 为 True 时：Agent 的 Prompt 为 instruction = AGENT_INSTRUCTION（业务prompt） + get_ui_prompt（UI模板 + A2UI Schema）
  • use_ui 为 False 时：Agent 的 Prompt 为 instruction = get_text_prompt()
  • 用 LiteLlm 封装底层模型，注册工具列表 [get_restaurants]
  1. 使用 ADK Runner + Session
    定义一个runner，主要作用：
  • 维护对话 Session（ InMemorySessionService ）
  • 协调 LLM 调用、工具调用、记忆等事件流
  1. stream交互逻辑
    RestaurantAgent.stream(self, query, session_id) 是这个 Agent 的“统一入口”，对外暴露的是一个 async generator ：
  • 先处理 Session，保证 state 里有 base_url （用于工具里替换图片 URL）
  • 用 Runner.run_async 发起一次“用户消息”，并遍历事件流：
    • 中间事件：不断 yield {"is_task_complete": False, "updates": "...进度文案..."}
    • 最终事件：拼成 final_response_content （LLM 的完整输出）
    • 如果是 A2UI 模式：解析出 text + A2UI JSON，使用 jsonschema 校验 A2UI JSON，不合格时重试

把 Agent 接到 A2A + A2UI 协议上（AgentExecutor）

文件 ： agent_executor.py
这个类的职责是： 在 A2A 请求上下文中调用你的Agent，并把 Agent 的输出转换成 A2A 消息（TextPart / DataPart）

  1. 解析用户输入和 A2UI 事件
    首先准备两个 Agent：UI + 文本，这样可以根据客户端是否支持 A2UI 决定调用哪个 Agent。

在方法 execute(self, context, event_queue) 中，识别是否启用 A2UI 扩展（即UI模式）

解析请求消息里的内容，遍历 context.message.parts ：

  • 如果是 DataPart ，且包含 "userAction" ，说明是来源于 UI 的 ClientEvent（比如按钮点击）
  • 如果是 TextPart ，就是普通文本输入

构造适合 Agent 的自然语言 query（如 USER_WANTS_TO_BOOK: … ）。
通过这种方式把“UI 事件”变成 LLM 能理解的自然语言 query，交给前面定义好的 Agent 指令逻辑处理。
2. 调用 Agent 的 stream 方法
创建 / 取得 Task，并通过 Runner 流式执行

  1. 把 Agent 输出转换为 TextPart + A2UI DataPart
    当 item["is_task_complete"] 为 True 时， content 里是我们在 Agent 里已经设计好的 "自然语言 + ---a2ui_JSON--- + JSON" 输出结构，从 content 中提取出 text_content（自然语言） 和 json_string（JSON），分别转换为 TextPart、A2UI DataPart ：

create_a2ui_part(message) 来自 a2ui.a2ui_extension ，会把 A2UI JSON 包装成 A2A 协议里的 DataPart。最终 final_parts 会组成一个 A2A 消息，既有文本，又有 UI
4. 设置 Task 状态并发送结果
通过 TaskUpdater 把中间状态和最终结果写回 A2A 事件流

启动 A2A + A2UI 服务

文件：main.py
首先，加载环境变量以及API Key。

  1. 定义 AgentCard （名称、能力、A2UI 扩展、技能列表）

对外暴露Agent元数据（名称、描述、支持的输入输出类型、支持的扩展等），供 A2A 客户端、UI 发现与展示。
2. 用 A2AStarletteApplication + Uvicorn 启动 HTTP 服务
A2AStarletteApplication 会把你的 Agent 挂成 A2A 协议兼容的 HTTP 服务。同时，也可挂 /static 路径服务图片资源，方便 UI 用相对路径加载
